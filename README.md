# 💡 Плаза: графік відключень підгрупи 2.2

Cloudflare Worker для окремого Telegram-каналу, визначеного через секрет
`CHANNEL_ID` (це **не** канал `@svitlo_kyivshchyna` бота ДТЕК,
якщо ви не встановили його ID вручну).

## Нова поведінка

- **Без петель:** публікації в каналі або групі ніколи не пересилаються
  назад у канал. Telegram webhook приймає тільки приватний чат власника.
- **Резерв вручну:** власник пересилає боту текстовий графік ДТЕК з
  явною датою та заголовком `Підгрупа 2.2 відключення:`. Бот
  витягує лише підтверджені години 2.2, порівнює з останнім графіком
  і створює новий незакріплений пост тільки при зміні.
- Відповідь власнику: опубліковано / без змін / помилка.
- Поки публічні дані ДТЕК наздоганяють новий пересланий графік,
  бот не повертає старі години у вигляді нових дописів.
- Кожні **5 хвилин** Cloudflare cron завантажує публічний підтверджений
  денний графік із `XOTT69/dtek/state/publications.json`.
- Надсилається **лише підгрупа 2.2**. Якщо даних `fact` для всіх 12
  підгруп на дату немає, нічого не вигадується і не публікується.
- При першій появі графіка на сьогодні — **«Графік відключення світла»**,
  на завтра — **«Графік відключення світла на завтра»**. У кожному дописі
  обов'язково вказано абсолютну дату.
- При **реальній зміні годин** створюється **новий незакріплений**
  допис із заголовком **«Оновлений графік відключення світла»**
  або **«Оновлений графік відключення світла на завтра»**.
  Бот не редагує старі повідомлення.
- Заголовок формується в момент публікації за київською датою,
  однаково для автоматичного й ручного режимів.
- Перехід **завтра → сьогодні**, зміна статусу екстрених відключень,
  тексту чи заголовка без зміни годин та повторний запуск
  **не створюють нового допису**: перевірка дублів залежить
  тільки від календарної дати й фактичних інтервалів.
- У кожному графіку — нейтральне попередження, що під час екстрених
  відключень погодинні графіки можуть не діяти. Не додаємо тимчасовий
  статус, який швидко застаріває у вже опублікованому дописі.
- Збереження останньої підтвердженої версії графіка в SQLite Durable
  Object захищає від повторів після перезапусків воркера. Втрачені
  відповіді Telegram переводять нову публікацію в стан `pending`.
- Міграція зі стану старої версії: вже оголошений і незмінний графік
  не публікується вдруге.

## Налаштування повністю онлайн (без Mac, Terminal чи Wrangler)

1. Увійдіть до [Cloudflare Dashboard](https://dash.cloudflare.com/)
   → **Workers & Pages**. Знайдіть Worker **plazagrafik**.

   - Якщо він уже існує: відкрийте **Settings → Builds → Connect**.
   - Якщо його немає: **Create application → Import a repository (GitHub)**.
   - У GitHub виберіть **XOTT69/plazagrafik**, гілка **main**.
   - Ім'я Worker обов'язково **plazagrafik** (як у `wrangler.toml`).
   - Build command: порожнє. Deploy command: `npx wrangler deploy`.
   - Натисніть **Save and Deploy**. Cloudflare автоматично
     оновлюватиме Worker після Git push.

2. Відкрийте Worker → **Settings → Variables and Secrets**.
   Налаштуйте в **production environment**:
   - `BOT_TOKEN` — чинний токен *саме цього* Telegram-бота, тип Secret;
   - `CHANNEL_ID` — числовий ID потрібного основного каналу або групи;
   - `ADMIN_TELEGRAM_ID` — *ваш власний* числовий Telegram ID, тип Secret.

   Якщо `BOT_TOKEN` і `CHANNEL_ID` вже є у старого Worker — не чіпайте їх.
   Всі значення вводяться тільки в Cloudflare. **Нічого секретного в GitHub
   код або ChatGPT чат вставляти не потрібно.**

   `WEBHOOK_SECRET` **необов'язковий**. Якщо раніше був збережений, бот
   використовуватиме його. Інакше сам детерміновано згенерує секрет
   підпису з `BOT_TOKEN` без зберігання чи відображення його на екрані.

3. Для безпечного керування webhook додайте в Cloudflare → Worker
   **plazagrafik** → **Settings → Variables and Secrets** новий
   **Secret** з назвою `SETUP_KEY` (щонайменше 24 символи). На сторінці
   `https://plazagrafik.<your-subdomain>.workers.dev/setup` є
   кнопки «Згенерувати ключ» і «Копіювати ключ». Створіть ключ у браузері,
   збережіть його як Secret тільки в Cloudflare і введіть на тій же сторінці.

   Натисніть **«Перевірити Telegram-бота»**. Сторінка після правильно
   введеного SETUP_KEY безпечно покаже `@username` бота й **лише домен**
   чинного webhook (не показує токен, шлях із секретами чи параметри URL).

   Переконайтеся, що це **саме бот графіків**, а не інший Telegram-бот
   («Світло є / Світло зникло» тощо). Введіть показаний `@username`,
   підтвердьте згоду та натисніть **«Перенести резервне пересилання»**.

   При перенесенні нового webhook Telegram автоматично перестане
   надсилати приватні повідомлення на стару адресу. Новий Worker
   прийматиме їх за адресою `/telegram` з підписом secret_token.
   **Автоматичний cron працює незалежно від webhook, а старі графіки
   автоматично не видаляються і не редагуються.**

   Система відмовить у перенесенні, якщо Telegram bot username не
   збігається, старий webhook змінився з моменту перевірки або
   неправильний SETUP_KEY. POST-операції не дають встановити чужу URL.

   **Увага:** Telegram-бот підтримує тільки один webhook одночасно.
   Якщо старий webhook також виконував інші команди або завдання,
   після перенесення вони не працюватимуть, доки їх не реалізовано
   в новому Worker. Переносьте лише webhook окремого бота графіків.

4. В особистому чаті саме з цим ботом перешліть **текстове**
   повідомлення ДТЕК з датою сьогодні/завтра та блоком
   `💡Підгрупа 2.2 відключення:` і часовими інтервалами
   `❌з 15:00 до 19:00`. Бот відповість результатом у приватному чаті.

   **Важливо:** фото без текстового підпису не можна розпізнати
   цим резервним парсером. Вхідні повідомлення в каналі, чужі графіки
   та повідомлення від сторонніх Telegram ID ігноруються.

5. Cloudflare Cron перевіряє підтверджені графіки ДТЕК раз на 5 хвилин
   і створює **новий** незакріплений допис тільки при новій даті або
   реальній зміні годин 2.2. Те саме переслане повідомлення не
   публікується двічі: автоматичний і ручний режими мають спільну
   перевірку стану через SQLite Durable Object.

Після першого підключення **GitHub → Cloudflare Builds** нові коміти в
`main` оновлюватимуть Worker автоматично.

`XOTT69/dtek` і `XOTT69/botvoda` залишаються незалежними.

## Діагностика: графік 2.2 не прийшов на завтра

В особистому чаті з `@plazakvartalbot` **лише власник** (Cloudflare
`ADMIN_TELEGRAM_ID`) може запустити:

- `/syncstatus` — показує, чи **дійсно запускався Cron**, час останньої
  перевірки, результат для сьогодні/завтра, `pending`, `manualHold`
  та збережені ID Telegram-дописів. Команда лише читає стан.
- `/status22` — додатково запитує свіжий підтверджений графік 2.2
  з GitHub і порівнює його зі станом Durable Object, без надсилання.
- `/sync22` — читає підтверджений графік саме **на завтра** та
  проходить звичайний захищений шлях публікації. Незмінний допис
  не відправляється повторно; якщо попередня доставка має статус
  `pending`, автоматичний дубль заборонено.

Перевірте в **Cloudflare → Workers & Pages → plazagrafik →
Deployments**: останній успішний deploy після коміту з командами,
а в **Settings → Triggers** має бути Cron `*/5 * * * *`. Якщо
`/syncstatus` не спрацьовує, це не доводить помилку ДТЕК:
можливо, Cloudflare працює на старому коді або webhook налаштований
на інший Worker. GitHub Actions перевіряє лише тестування/збірку і
**не розгортає** цей Worker автоматично без окремого підключення
Cloudflare Builds.

Для будинку **Покровська, 30Б** перевіряйте також Cloudflare
`CHANNEL_ID`: у ньому має стояти ID потрібної групи/каналу
«Світло Покровська 30б», а не іншого Telegram-чату.
Не надсилайте токени або `SETUP_KEY` у повідомленнях.

## Відмова мережі й захист від дублів

Якщо Telegram не відповів на новий `sendMessage`, стан дати
позначається `pending`. Це свідомий режим **без повторної відправки**,
щоб не отримати дубль, якщо Telegram прийняв повідомлення, але
відповідь загубилася. Такий випадок треба розібрати по логах і
порівняти фактично опубліковане повідомлення з Durable Object.

Видалення старого допису вручну не спричиняє повторну публікацію
того самого графіка: наступний допис буде лише після підтвердженої
зміни інтервалів або появи графіка на іншу дату.

Тести: `npm test`. Перевірка бандла: `npm run check`.

**Увага:** перенесення стороннього webhook можливе тільки після SETUP_KEY, перевірки бота за username та явного підтвердження власника.

## Захист від пропущених публікацій (оновлення 24.10.2026)

Якщо Telegram не повернув ID допису, **той самий** графік залишається
у `pending`, щоб не створити дубль. Але нова підтверджена версія з
іншими годинами тепер може бути автоматично опублікована без блокування
на весь день. Через 10 хвилин невизначеного результату бот один раз
надсилає власнику попередження, якщо налаштовано `ADMIN_TELEGRAM_ID`.
Після перевірки відсутності повідомлення в каналі команда
`/recover22 ДАТА CONFIRM` дозволяє опублікувати **поточні**
підтверджені години, навіть якщо вони відрізняються від попередньої
завислої версії. Команда надалі не обходить підтвердження власника.

Захист від дублікатів одного невизначеного `sendMessage` збережено:
Telegram Bot API не надає ключа ідемпотентності для цього методу,
тому автоматичне повторення тотожного повідомлення після timeout
могло б призвести до дубля.

## Особисте меню в Telegram (етап 1)

Канали та їхні автоматичні дописи **не змінюються**. На чинному
`@plazakvartalbot` уже налаштований webhook `/telegram`:
після автоматичного деплою напишіть йому в приватний чат **`/start`**.

Для мешканців доступні кнопки: **Сьогодні, Завтра, Зараз, Наступне,
Статистика, Календар, Поділитися, Допомога, Налаштування**.
У Плазі зафіксована підгрупа 2.2. У персональній відповіді бота
показується **плановий** стан, а не фізичне підтвердження електрики.
Пересилання власником оригінального графіка в приватний чат і
автоматичні публікації каналу збережені. Поточні ручні оновлення
Плази мають пріоритет при перегляді годин у приватному боті.

### Підключення персонального меню загального ДТЕК-бота

Для `@svitlo_kyivshchyna_bot` вихідні канальні публікації надалі
виконує `XOTT69/dtek` через GitHub Actions. Для приватного меню
потрібно одноразово підключити **окремий** вхідний Telegram webhook:

1. Cloudflare → **plazagrafik** → Settings → Variables and Secrets.
   Додайте **Secret** `DTEK_BOT_TOKEN`, використовуючи токен
   **саме `@svitlo_kyivshchyna_bot`**. Не змінюйте `BOT_TOKEN`,
   `CHANNEL_ID`, токени або webhook Плази. Не копіюйте токен
   у GitHub чи чат.
2. Переконайтеся, що чинний `SETUP_KEY` є в Cloudflare.
   Відкрийте
   `https://plazagrafik.mikolenko-anton1.workers.dev/setup-dtek`,
   введіть **свій `SETUP_KEY`**, натисніть
   **«Перевірити Telegram-бота»**. Повинен відобразитися
   **`@svitlo_kyivshchyna_bot`**.
3. Якщо це точно потрібний бот, підтвердьте його username та
   підключення вебхука. Telegram скерує тільки приватні повідомлення
   цього бота на `/telegram/dtek` (з окремим secret_token).
   Підписники каналу та GitHub Actions не змінюються. Якщо
   на цьому боті раніше був інший webhook, перевірте перед
   перенесенням, чи його функції не потрібні.
4. В особистому чаті з `@svitlo_kyivshchyna_bot` відправте
   **`/start`**, виберіть **«Моя підгрупа»** та перевірте
   кнопки «Сьогодні», «Завтра», «Зараз».
   Вибір зберігається окремо для кожного Telegram ID у вже
   наявному SQLite Durable Object.

При відсутності повного підтвердженого DTEK графіка за день
бот повідомляє про відсутність даних; не вигадує інтервали.

**Важливо:** персональні проактивні нагадування, керування нічною
розсилкою, графічна 24-годинна Mini App, довгі історії версій,
сімейна синхронізація та повна адмінпанель — **наступні етапи**.
Поточна кнопка «Налаштування» чесно повідомляє, що розсилку
ще не запущено. У каналах і надалі працюють їхні вже чинні нагадування.
