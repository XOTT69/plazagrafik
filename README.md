# 💡 Плаза: графік відключень підгрупи 2.2

Cloudflare Worker для окремого Telegram-каналу, визначеного через секрет
`CHANNEL_ID` (це **не** канал `@svitlo_kyivshchyna` бота ДТЕК,
якщо ви не встановили його ID вручну).

## Нова поведінка

- **Без петель:** публікації в каналі або групі ніколи не пересилаються
  назад у канал. Telegram webhook приймає тільки приватний чат власника.
- **Резерв вручну:** власник пересилає боту текстовий графік ДТЕК з
  явною датою та заголовком `Підгрупа 2.2 відключення:`. Бот
  витягує лише підтверджені години 2.2, порівнює з останнім графіком
  і створює новий незакріплений пост тільки при зміні.
- Відповідь власнику: опубліковано / без змін / помилка.
- Поки публічні дані ДТЕК наздоганяють новий пересланий графік,
  бот не повертає старі години у вигляді нових дописів.
- Кожні **5 хвилин** Cloudflare cron завантажує публічний підтверджений
  денний графік із `XOTT69/dtek/state/publications.json`.
- Надсилається **лише підгрупа 2.2**. Якщо даних `fact` для всіх 12
  підгруп на дату немає, нічого не вигадується і не публікується.
- При першій появі підтвердженого графіка — один звичайний
  (не закріплений) текстовий допис на календарну дату.
- При **зміні підтверджених годин** — окремий новий незакріплений
  текстовий допис. Бот не редагує старі повідомлення.
- Перехід **завтра → сьогодні**, зміна статусу екстрених відключень або
  повторний запуск без змін графіка не спричиняє новий допис.
- У кожному графіку — нейтральне попередження, що під час екстрених
  відключень погодинні графіки можуть не діяти. Не додаємо тимчасовий
  статус, який швидко застаріває у вже опублікованому дописі.
- Збереження останньої підтвердженої версії графіка в SQLite Durable
  Object захищає від повторів після перезапусків воркера. Втрачені
  відповіді Telegram переводять нову публікацію в стан `pending`.
- Міграція зі стану старої версії: вже оголошений і незмінний графік
  не публікується вдруге.

## Підключення (один раз)

1. Переконайтеся, що бот — адміністратор **потрібного основного каналу** або групи
   та має право публікувати повідомлення.
2. Cloudflare Worker `plazagrafik` повинен мати секрети:
   `BOT_TOKEN` — токен бота, `CHANNEL_ID` — ID цільового каналу.
   **Не записуйте токен у GitHub чи цей README.**
3. На Mac відкрийте Terminal і виконайте:

   ```bash
   git clone https://github.com/XOTT69/plazagrafik.git
   cd plazagrafik
   npm install
   npx wrangler login
   npm run deploy
   ```

   Якщо папка `plazagrafik` вже існує, у ній зробіть `git pull`
   замість повторного клонування. Потрібен Node.js 20+.

4. Wrangler створить SQLite Durable Object за міграцією `v1` та активує
   cron `*/5 * * * *`. Вручну KV namespace не потрібен.
5. Збережіть в Cloudflare Worker (не в GitHub!) секрети:

   ```bash
   npx wrangler secret put BOT_TOKEN
   npx wrangler secret put CHANNEL_ID
   npx wrangler secret put ADMIN_TELEGRAM_ID
   npx wrangler secret put WEBHOOK_SECRET
   ```

   Вводьте значення кожного секрету лише в Terminal. `BOT_TOKEN`
   — токен Telegram-бота; `CHANNEL_ID` — ID цільового каналу або групи;
   `ADMIN_TELEGRAM_ID` — ваш власний числовий Telegram ID. Його можна
   дізнатися в `@userinfobot`. `WEBHOOK_SECRET` — випадкові 32–64
   символи A-Z, a-z, 0-9, `-`, `_` (можна створити `openssl rand -hex 24`).
   Якщо `BOT_TOKEN` / `CHANNEL_ID` уже збережені в Worker, повторно
   їх задавати не потрібно.
6. У результаті `npm run deploy` знайдіть реальну адресу Worker,
   наприклад `https://plazagrafik.<ваш-піддомен>.workers.dev`.
   Перевірте, що Telegram `getWebhookInfo` відповідає за цей самий бот,
   потім встановіть webhook на адресу `/telegram` і **той самий секрет**:

   ```bash
   read -s -p 'Telegram bot token: ' TOKEN; echo
   read -s -p 'Webhook secret: ' SECRET; echo
   curl -sS -X POST "https://api.telegram.org/bot${TOKEN}/setWebhook" \\
      --data-urlencode "url=https://plazagrafik.<ваш-піддомен>.workers.dev/telegram" \\
      --data-urlencode "secret_token=${SECRET}" \\
      --data-urlencode 'allowed_updates=["message"]'
   unset TOKEN SECRET
   ```

   На macOS `read -s -p` може не працювати: в такому разі введіть
   `read -s TOKEN; echo` та `read -s SECRET; echo` окремо, без показу
   секретів. **Не надсилайте токени в чат.**
7. Дочекайтеся наступної перевірки. У логах: `npx wrangler tail`.
   Для резервної перевірки перешліть із власного Telegram акаунта боту
   датований графік 2.2 в **особисті повідомлення**.
   Повторне пересилання ідентичного графіка не створить нового допису.

Публікації в `XOTT69/dtek` та `XOTT69/botvoda` не змінюються.
Новий webhook приймає тільки підписані Telegram запити власника в приватному
чаті. Пости в каналі та повідомлення сторонніх користувачів ігноруються.

## Відмова мережі й захист від дублів

Якщо Telegram не відповів на новий `sendMessage`, стан дати
позначається `pending`. Це свідомий режим **без повторної відправки**,
щоб не отримати дубль, якщо Telegram прийняв повідомлення, але
відповідь загубилася. Такий випадок треба розібрати по логах і
порівняти фактично опубліковане повідомлення з Durable Object.

Видалення старого допису вручну не спричиняє повторну публікацію
того самого графіка: наступний допис буде лише після підтвердженої
зміни інтервалів або появи графіка на іншу дату.

Тести: `npm test`. Перевірка бандла: `npm run check`.

**Увага:** Telegram-бот має тільки одну активну адресу webhook.
Не змінюйте її для токена, який одночасно обслуговує інший важливий
проєкт. Перед зміною переконайтеся, що це саме бот `plazagrafik`.
